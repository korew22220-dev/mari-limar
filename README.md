# MARLI LIMAR — публикация и обновление

Сайт подготовлен из предоставленного архива. Деплой ещё не выполнен.

## Публикация на GitHub Pages

1. Создать публичный репозиторий `marli-limar` в аккаунте `korew22220-dev`.
2. Загрузить содержимое этого каталога в корень ветки `main`, включая `.github/workflows/pages.yml`. Не загружать ZIP вместо файлов. Убедиться, что `index.html` находится в корне.
3. В Settings → Pages выбрать Source → GitHub Actions.
4. В Actions запустить `Publish MARLI LIMAR` (Run workflow) либо внести следующий коммит в `main`.
5. Дождаться успешного задания Deploy. Открыть адрес из результата задания. До этого публикация не подтверждена.
6. Проверить каждую страницу, меню, фильтры и видео на телефоне, планшете и компьютере; проверить отсутствие ошибок загрузки.

Workflow публикует только HTML, MP4 и assets. README и служебные материалы в опубликованный сайт не входят. Canonical, og:url и sitemap.xml создаются автоматически по реальному адресу Pages при деплое.

## Обновление

- Тексты редактировать в соответствующем HTML: index, kitchens, architecture-design, portfolio, expertise, about, contacts, blog и четыре blog-*.html.
- Фотографии лежат в assets. При замене сохранять имя либо менять все ссылки на него. Использовать WebP и прописывать реальные размеры изображения.
- Общие исправления поведения — assets/site.js; дополнительные стили — assets/site-fixes.css. styles-*.css содержат прежние стили, вынесенные из HTML без переработки дизайна.
- В kitchens.html менять карточки РИМИ, значения фильтров и список выбора модели согласованно.
- В portfolio.html для проекта указывать статус: realized, concept, visualization или reference. Обновлять и карточку, и массив projects для её модального окна. Сейчас все шесть карточек — референсы, а не выполненные работы студии.
- Чтобы добавить статью, скопировать одну из blog-*.html, заменить содержание, title, description и Open Graph; добавить карточку и ссылку в blog.html. Sitemap обновится при деплое.
- После коммита в main публикация запускается автоматически. При ошибке открыть журнал Actions; для отката отменить проблемный коммит через Revert.
- Не загружать .env, пароли, токены и клиентские персональные данные. Сайт статический: секреты нельзя хранить в JavaScript.

## Что нужно от заказчика

- Подтверждённые телефон, почта, мессенджеры, адрес, часы работы, точка на карте.
- Способ приёма заявок и необходимые согласованные тексты для формы. Сейчас формы отправки нет; ссылки связи открывают страницу с обозначенными заглушками.
- Реальные проекты: фото, названия, описания, разрешения на публикацию, отдельно статус каждого объекта — реализация, концепция или визуализация.
- Портрет Марины Литовкиной и разрешение на его использование.
- Подтверждение квалификации эксперта и формулировок услуги, образец заключения, порядок и стоимость работы. Исходные оговорки на странице сохранены.
- Подтверждение актуальности коллекций РИМИ, отделок и доступности; разрешения на использование материалов каталогов.
- Финальное согласование статей и авторства. В исходнике есть редакционные пометки — они сохранены.
- Отдельный исходник логотипа для favicon (SVG либо качественный PNG). В архиве только текстовое название и видео; отдельного логотипа нет.

## Проверки и ограничения

- Проверены существование страниц, локальные ссылки и якоря, изображения, отсутствие повторных id, синтаксис JavaScript, декодирование всего видео и типовые шаблоны секретов.
- Внешние референсные фотографии сохранены локально в WebP. Исходные WebP РИМИ сохранены. Видео H.264 1280×720, 17,375 с; faststart без повторного сжатия и отдельный poster.
- Шрифты Manrope и Italiana продолжают загружаться через Google Fonts; предусмотрены исходные резервные системные шрифты.
- Browser QA в этой среде недоступен. Реальное автозапускание видео, клики, внешний вид и отсутствие переполнения на всех размерах экрана не подтверждены браузерным тестом.
- GitHub-подключение позволило проверить список репозиториев, но не предоставляет создания репозитория и включения Pages. Публикация и её URL не подтверждены.
